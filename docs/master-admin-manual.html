1. Your role and signing in

You are the site admin (master admin) for TouristQR. Sponsors manage only their own profile and listings. You manage the whole catalogue: every sponsor, subscription dates, categories, site-wide notice, catalogue backups, and phone signup.

Sign in

  1. Open admin.html on the live site (or your staging copy).
  2. Enter your site-admin username and password.
  3. After sign-in, the header shows Signed in as … · site admin.

Sponsors use the same page with their own login; they do not see admin-only panels (catalogue totals, add sponsor, backup all, categories, generic QR sheets, phone signup).

What visitors see

The public heritage, shop, restaurant, and exhibit pages do not require a login. Changes you or sponsors save in the console appear on the public site after save (and after visitors refresh).

Security: Do not share the site-admin password. Give each sponsor their own login. Change compromised passwords from the sponsor profile (login name / password fields) or by recreating the login when adding a sponsor.

2. Console layout and work modes

The console is a single scrolling page of panels. Use the Catalogue buttons to switch work mode:

ModeUse for
SitesHistoric site sponsors; many listings per sponsor; heritage categories.
ShopsShop sponsors; one listing per sponsor; appears under Shops on the public page.
RestaurantsRestaurant sponsors; one listing; appears under Restaurants.
ExhibitsExhibit sponsors; club logo on profile; exhibit categories.

The yellow Select sponsor panel lists sponsors for the current mode. Tick Sort by expiry to see whose public listing ends soonest first.

Typical workflow

  1. Choose work mode (Sites, Shops, etc.).
  2. Pick a sponsor from the dropdown (or add a new one).
  3. Edit Sponsor profile (business name, contact, login, subscription start).
  4. Edit Page Data for each listing (text, location, photos).
  5. Use the QR code panel to download a PNG for printing.

Tap the i on Catalogue, Sponsor profile, Page Data, QR, or Backup panels for short in-app help.

3. Adding sponsors and welcome email

Phone signup (recommended in the field)

  1. Tap Phone signup in the admin header.
  2. Choose Site, Shop, or Restaurant; fill business and contact details.
  3. Assign login name and password (or let the flow create them).
  4. Scan or enter a Generic QR code to bind the new listing number.
  5. On success, the contact receives a welcome email with public link, admin link, login, dates, backup reminder, and referral offer.

Add sponsor (from the console)

Expand Add sponsor, complete the form for the current work mode, and submit. This creates the sponsor record and login. You still add or edit listing content under Page Data.

Welcome email wording

The signup email text lives in content/welcome-signup-email.json on the server. Edit subject, text, and html there (keep JSON valid). Placeholders such as {{businessName}} and {{username}} are filled in automatically. The same file supplies the short backup callouts beside download buttons in admin.

After FTP upload of that file, new signups use the new wording; sponsors see updated callouts when they sign in again.

4. Listings, photographs, and QR codes

Page Data

  • Historic sites / exhibits: place name and history text are required before save. Site admin sets the permanent listing id (lowercase, numbers, hyphens).
  • Shops / restaurants: one listing per sponsor; shop name and description; optional website.
  • Use + Next new site (or exhibit equivalent) for additional listings under the same site sponsor.

Photographs

  • Up to 20 photos per listing. Files are stored as sponsor number-reference.jpg (e.g. 4-003.jpg).
  • Normal gallery (main carousel): 4∶3, max 1200×900 px.
  • Special strip (Historical, shop front, or advertising): 16∶9, max 1200×675 px — mark one photo per listing in Page Data.
  • Club logo (exhibit sponsors, Sponsor profile): 128×128 px square.
  • Order: Move up / Move down, then Save. Replacing a photo keeps its code; removed codes are not reused.

QR codes

  • Each listing has a public URL on touristqr.com. The QR panel shows the code for the listing you have open.
  • Download QR image for print. If you change listing id or public address, regenerate after save.
  • Generic signup codes are separate: see section 6.

Deleting

Delete site removes the listing from the catalogue but leaves image files on the server so numbers are not reused. Delete this sponsor (admin only) removes the sponsor, login, all their listings, their photo files, and frees their Generic number—use only when you mean to remove them completely.

5. Subscriptions, notice, and categories

Public listing period

Each sponsor has a Subscription start date (site admin only on the profile). The listing stays on the public site for 12 months, plus any referral bonus months, then has one grace month before it is archived. The status pill shows Active · till ….

Referrals: when a new business names an existing sponsor at signup, that sponsor gains one extra month. They can quote the referrer’s Generic code or login name.

Message to every sponsor

The Message to every sponsor panel saves a short notice (max 400 characters) shown to every sponsor under their session line after sign-in. Use it for deadlines, events, or backup reminders.

Site categories

While in Sites work mode, the category editor lists heritage categories for the public Category filter. Rename updates all sites using that name; delete moves them to Uncategorised. Shop, restaurant, and exhibit category lists are managed separately in data settings—contact your technical maintainer if those need changing.

6. Backups and instant signup QR sheets

Who is responsible

Your web host may snapshot the whole server. TouristQR also offers downloadable backups. Sponsors must keep their own copies; you must keep catalogue-level copies for disaster recovery.

ActionWhoWhat it does
Download my data Sponsor (or you on their profile) JSON with their profile, listings, photos, and club logo packed inside. Restore replaces only that sponsor—no Save button needed after restore.
Download catalogue backup Site admin only Full JSON: all sponsors, listings, images, logins, settings. Restore replaces the entire catalogue—confirm carefully.

Store backup files off the website (computer, USB, cloud). Test restore on a copy of the site when you can.

Instant signup QR codes

  1. Set Start number; leave Skip numbers already used on unless you intend to reuse a sheet.
  2. Make 6 codes then Print A4—six Generic codes per sheet.
  3. Hand sheets to volunteers; each code can bind one new signup.

Recover one sponsorTheir backup file → Restore my data
Recover whole site contentCatalogue backup → Restore catalogue backup
Edit welcome emailcontent/welcome-signup-email.json on server

If something goes wrong

  • Save failed / red message: read the text; often validation (missing email, history, or login rules). Fix the field and save again.
  • Photos missing after restore: the backup file must include embedded photos; if the backup was old or incomplete, restore from a newer file or host snapshot of the images folder.
  • Sponsor cannot sign in: check login name on profile; reset password; ensure their organisation is still in the catalogue.
  • Public page not updating: hard refresh the browser (Ctrl+F5). Confirm save succeeded in admin.

Deploy reminder

When your maintainer updates the site, upload changed files via FTP and hard-refresh admin. Bump cache versions on JS/CSS if instructed.

8. SEO (search engines)

Public listings are meant to appear in Google and other search engines. Admin, signup, and this manual are set to noindex so they do not compete with the public catalogue.

  • Homepage wording: edit content/seo-defaults.json on the server (title and description for the whole site).
  • Each listing: use a clear place name, history text, city/suburb, and photographs — the app updates page title, description, and sharing tags when someone opens that listing.
  • Sitemap: https://touristqr.com/sitemap.xml lists the homepage and every public listing (regenerated from the catalogue).
  • robots.txt at the site root points crawlers to the sitemap and blocks /data/ and admin URLs.
  • Social preview & icon: replace images/touristqr-social.jpg (link previews) and images/touristqr-icon.jpg (browser tab) or change paths in content/seo-defaults.json.

After deploy, register the site in Google Search Console (free) and submit the sitemap URL once.
